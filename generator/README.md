# Генератор Blog

Нужен Python 3. Дополнительные библиотеки не требуются. Blog должен быть уже запущен.

Автоматическая демонстрация для скринкаста (также нужен `kubectl` с доступом к Minikube):

```bash
python3 generator/demo.py
```

Отдельно генератор запускать не нужно. Сценарий создаёт группы по 10 попыток сразу, через 5 и через 10 минут. На 4:50 включает ошибки 503, на 5:45 — задержку 1,2 секунды на минуту, на 7:00 повторно отключает воздействие. Через 15 минут завершается. Во второй группе регистрации намеренно завершаются ошибкой; успешных аккаунтов будет меньше 30. Этапы выводятся в терминал. Графики обновляются с задержкой сбора метрик.

**Ctrl+C** останавливает сценарий и генератор, затем отключает воздействие во всех работающих pod Blog. При недоступности Kubernetes ошибки сами истекают через 120 секунд, задержка — через 60 секунд после включения. Учебные данные остаются для просмотра; очистка приведена ниже. Параллельно два автоматических сценария запустить нельзя. Для других адреса, контекста или namespace используйте `--url`, `--context`, `--namespace`.

Из корня проекта запустить нагрузку на 15 минут:

```bash
python3 generator/run.py
```

По 10 пользователей каждые 5 минут в течение 15 минут:

```bash
python3 generator/run.py --seconds 900 --batch-size 10 --interval 300
```

Группы начинаются на 0-й, 5-й и 10-й минутах; на 15-й минуте генератор завершится. Внутри группы аккаунты создаются последовательно, без специальной паузы. Без ошибок получится 30 пользователей, 30 постов и 30 комментариев. При ошибках попыток останется 30, а успешных созданий будет меньше. Если запросы выполняются настолько долго, что группа не успела закончиться до конца запуска, попыток тоже будет меньше. Уже начатый цикл завершается, поэтому остановка может быть немного позже 15 минут.

Создать 10 пользователей:

```bash
python3 generator/run.py --users 10
```

Другие варианты:

```bash
python3 generator/run.py --seconds 300 --interval 5
python3 generator/run.py --users 20 --interval 1
python3 generator/run.py --url http://127.0.0.1:8001 --seconds 900
```

Генератор регистрирует пользователей через формы сайта. Первый аккаунт создаёт посты и комментарии, читает пост. Следующие регистрации выполняются независимо от этих действий, поэтому при ошибках регистрации остальные SLI продолжают проверяться.

В обычном режиме каждый цикл создаёт одного пользователя, один пост и один комментарий. `--batch-size` задаёт число циклов в группе, `--interval` — интервал между началами групп в секундах. По умолчанию это один цикл каждые 5 секунд. Пропущенные из-за долгих запросов начала групп не наверстываются. `--users` ограничивает общее число попыток регистрации; при ошибках созданных аккаунтов может быть меньше. Нормальные коды: `registration=302`, `post=302`, `read=200`, `comment=302`. Код `0` означает сетевую ошибку. Остановка: **Ctrl+C**.

`run.py` создаёт только нагрузку, `demo.py` запускает нагрузку вместе с ошибками по расписанию.

Для просмотра откройте Grafana на `/d/blog-slo-sla/`, выберите последние 15 минут,
обновление каждые 15 секунд и окно SLA «2 минуты». Сначала наблюдайте успешные
действия, с 4:50 — ошибки, с 5:45 — рост времени ответа, после 7:00 —
восстановление. Третья группа на 10-й минуте снова проверяет успешные действия.
Между группами бизнес-SLI могут показывать `No data`: новых попыток нет.
Пробер при этом продолжает проверять доступность. Окно SLA «1 час» сохраняет
сведения о сбое дольше, чем окно «2 минуты».

Если Blog недоступен по адресу выше, оставьте работать в отдельном терминале:

```bash
kubectl --context=blog-sre -n blog-sre port-forward svc/blog-web 8001:80
```

Каждый запуск получает отдельный JSON-файл в `artifacts/generator/`. Его путь выводится при запуске. В нём сохранены имена аккаунтов, общий пароль этого запуска и результаты. Для входа используйте имя из `registered_users` и значение `password`. Файлы доступны только владельцу, исключены из Git и Docker-образа. Предыдущие файлы не перезаписываются.

После остановки генератора удалить данные его последнего запуска в Minikube:

```bash
python3 generator/run.py --cleanup latest
```

Для более раннего запуска укажите выведенный им путь:

```bash
python3 generator/run.py --cleanup artifacts/generator/ИМЯ_ФАЙЛА.json
```

Очистка работает через `kubectl` в контексте и namespace `blog-sre`. Удаляются только аккаунты из проверенного списка этого запуска и их содержимое. Работающий запуск очистить нельзя. Повторная очистка того же файла безопасна. Для другого контекста или namespace используйте `--context` и `--namespace`.

```bash
python3 generator/run.py --help
```

Проверки генератора без доступа к рабочей базе:

```bash
python3 -B -m unittest discover -s generator/tests -v
```
